# 기회ON

```bash
npm install
npm run dev
```

서버가 출력하는 주소를 브라우저에서 엽니다. `npm run build`는 정적 배포용 `dist`를 생성합니다.

- 발표 추천: `/?demo=1&view=recommend`
- 발표 준비함: `/?demo=1&view=prep` (발표 기록이 없는 브라우저에서 샘플 상태로 시작)
- 발표 기록을 지우려면 발표 모드 상단의 시연 초기화를 누르세요.

공고는 `src/notices.json`에서 수정합니다. `category`와 `tags`는 각각 분류와 추천 관심 분야입니다. `override`에 모집 상태 텍스트를 넣으면 날짜 계산보다 우선하므로 조기 종료를 반영할 수 있습니다. 실제 공식 원문 확인 전 예시 공고의 `official`을 켜지 마세요. 대표 공고는 제공받은 시연 정보이며 개별 원문을 확인하지 못해 굿길 첫 화면으로 연결합니다. 비로그인 시 시연 기록은 브라우저에 보관되고, 로그인 시 사용자별 데이터는 Supabase에 저장됩니다.

## 공개 공고 데이터 갱신

`python -m pip install beautifulsoup4` 후 `python scripts/update_official.py`와 `npm run build`를 실행합니다. 학교 한경공지·장학공지의 첫 페이지와 굿길 첫 화면에 공개된 비교과 프로그램을 수집해 `src/official.json`을 갱신합니다. 브라우저에서 실시간으로 가져오는 구조는 아니며, 로그인 뒤의 공고나 다른 게시판·페이지 전체를 포함한다고 보장하지 않습니다. 키워드 추천은 신청 자격 판정이 아닙니다. 학교 공고의 게시일은 신청 마감이 아닙니다. 출처 중 하나라도 갱신에 실패하거나 공고가 비어 있으면 기존 파일을 유지합니다. 데이터 이용과 자동 수집의 허용 범위는 운영 전 학교에 확인해야 합니다.

학교 공식 시그니처와 한경이 이미지는 각각 한경국립대학교의 [로고 및 UI](https://www.hknu.ac.kr/kor/601/subview.do), [한경캐릭터](https://www.hknu.ac.kr/kor/602/subview.do)에서 가져왔습니다. 학교와 무관한 학생 제안작임을 화면에 명시합니다.

## 화면 및 내 정보

홈 `#/home`, 공고 찾아보기 `#/explore`, 내 정보 `#/profile`, 내 준비함 `#/prep`은 각각 주소로 이동할 수 있습니다. 예: `?demo=1#/explore`. 프로필은 선택 사항이며 이름·학번을 입력하지 않습니다. 로그인한 사용자의 정보는 계정에 저장됩니다. 발표 모드와 일반 모드는 별도 저장됩니다. 굿길 공개 목록에서 확인 가능한 재학·학년과 개설 장소를 참고해 표시하며, 나머지 신청 조건은 원문 확인이 필요합니다. 굿길 공고의 학년·재학 조건에 불일치 가능성이 있으면 안내하며, 자동으로 신청 가능 여부를 판정하거나 공고를 제외하지 않습니다. 개설 장소는 신청 자격으로 취급하지 않습니다.

## 전공·경험 기반 추천

내 정보에서 전공을 입력하고 경험 분야를 복수 선택하면 `src/recommendation.ts`에 정의된 제목 키워드와 비교합니다. 컴퓨터공학·소프트웨어융합·정보보안 전공은 보안 및 프로그래밍 관련 주제와 연결됩니다. 선택한 경험 및 관심 분야와의 일치도 함께 반영하며, 관련성이 높은 공고를 먼저 보여주고 이유를 표시합니다. 이는 제목에 근거한 보조 추천으로 수상 가능성이나 신청 자격을 예측하지 않으며, 제목에 키워드가 없거나 표현이 다른 공고는 누락될 수 있습니다. 이름·학번은 입력하지 않으며 OpenAI 키는 필요하지 않습니다.

## 학부·전공 목록

`src/academics.ts`의 학부·전공 데이터는 [전공자율선택제 안내](https://www.hknu.ac.kr/kor/7010/subview.do), [안성 전체 학부](https://www.hknu.ac.kr/kor/4485/subview.do), [평택 전체 학부](https://www.hknu.ac.kr/kor/4501/subview.do) 및 개별 학부 소개를 참고한 수동 목록입니다. 학교의 자료마다 전공 이름과 소속 표기가 일부 다를 수 있고, 조직 개편 후에는 수정이 필요합니다. HK자율전공학부의 선택 항목은 2026학년도 전공 안내에 나온 희망 전공을 반영하며, 실제 소속·배정이나 신청 자격을 판정하지 않습니다. 기존 전공 입력값은 가능한 경우 학부에 자동 연결됩니다.

## Vercel 배포

GitHub에 프로젝트를 올린 후 Vercel에서 해당 저장소를 가져오면 됩니다. Vite 프레임워크, `npm run build` 빌드 명령과 `dist` 출력 디렉터리는 `vercel.json`에 설정되어 있습니다. Supabase 로그인 및 계정 저장을 사용하려면 아래 환경 변수를 Vercel에도 설정해야 합니다. 배포 후 `/?demo=1&view=recommend`와 `/?demo=1&view=prep`을 각각 발표용 주소로 사용할 수 있습니다.

공고 데이터는 빌드 시점의 공개 목록입니다. 새로운 공고를 반영하려면 위의 데이터 갱신 명령을 실행하고 결과 파일을 커밋하여 다시 배포해야 합니다. 로그인한 사용자의 프로필과 준비 기록은 Supabase에 저장됩니다.


## Supabase 로그인 및 계정 저장

Supabase 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행해 사용자 데이터 테이블과 행 단위 보안 정책을 생성합니다. Authentication에서 이메일 로그인과 이메일 확인을 설정하고, URL Configuration의 Site URL과 Redirect URLs에 실제 앱 주소를 등록하세요. 이메일 확인 후 돌아갈 주소는 이 앱의 실행 주소입니다. 운영 환경의 URL도 별도 등록해야 합니다.

프로젝트 설정의 URL과 공개 가능한 publishable(또는 anon) 키를 `.env.example`을 참고해 `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`로 저장한 다음 개발 서버를 재시작합니다. Vercel에 배포할 때도 동일한 환경 변수를 설정하고 다시 배포하세요. 서비스 역할 키나 비밀 키는 브라우저 코드와 환경 변수 `VITE_`에 넣지 마세요.

설정이 없으면 사이트는 기존처럼 사용할 수 있고 로그인은 준비 중으로 표시됩니다. 로그인하면 관심 분야, 준비 기록과 프로필이 계정별로 저장됩니다. 로그인 전 이 브라우저의 기록은 자동으로 계정에 복사되지 않고, 시연 모드는 브라우저에만 저장됩니다. 계정 정보가 불러와지지 않을 때는 덮어쓰지 않고 오류를 표시합니다.

## 랜딩 및 로그인 화면

비로그인 방문자는 랜딩에서 서비스를 소개받고 공개 공고를 둘러볼 수 있습니다. 회원가입·로그인과 비밀번호 재설정은 Supabase 이메일 인증을 사용합니다. 새 계정은 첫 로그인 시 관심 분야 선택을 볼 수 있으며 건너뛸 수 있습니다. 기존 데이터는 그대로 유지합니다. 학교·굿길 공개 공고와 교외 공고를 저장할 수 있습니다. 학교·굿길 공개 공고에는 준비 체크리스트가 제공되지 않습니다.

비밀번호 재설정 이메일을 사용하려면 Supabase Authentication의 Redirect URLs에 앱 주소와 앱 주소에 `?auth=recovery`를 붙인 주소를 추가하세요. 이메일 확인 URL도 해당 환경의 앱 주소가 Redirect URLs에 등록되어야 합니다. 기존 인증 이메일 링크가 `localhost` 등으로 돌아가는 경우 Site URL 설정과 이메일 템플릿을 확인하세요. 실제 운영 이용약관과 개인정보 처리방침은 아직 제공되지 않아 동의 체크박스를 임의로 만들지 않았습니다.


## 교외 공고 갱신과 일정

위비티의 공개 공고와 Devpost의 공개 해커톤 목록을 빌드 시점 데이터로 제공합니다. `python -m pip install beautifulsoup4` 후 `python scripts/update_external.py`를 실행하고 다시 빌드하면 목록이 갱신됩니다. 자동 갱신은 설정되어 있지 않습니다. 현재 수집에는 API 키가 필요하지 않으며, 출처별 이용 조건을 확인한 후 운영하세요. 수집 공고의 상세 조건과 마감 시각·시간대는 출처 및 주최 측 공고에서 확인해야 합니다.

저장한 공고의 확인 가능한 마감일과 직접 입력한 단일·기간 일정은 홈 캘린더에 표시됩니다. 한국시간 기준으로 마감일까지 7일 이내에는 노란 표시, 3일 이내에는 빨간 표시를 보여줍니다. 학교 공지의 게시일은 마감일로 취급하지 않습니다. 로그인 사용자의 일정과 저장 공고는 기존 계정 데이터에 저장되며 시연 모드의 데이터는 해당 브라우저에 저장됩니다.


## 데이터 보관과 공고 표시

로그인 사용자의 관심 분야, 저장한 공고, 체크리스트와 일정은 Supabase의 `user_data` JSON에 저장됩니다. 브라우저별 발표 모드 데이터는 `localStorage`에 저장하며 일반 계정과 별도입니다. 저장한 학교·굿길 공고가 새 공개 목록에 있으면 최신 항목을 우선 표시하고 목록에서 사라지면 저장 당시 내용을 유지합니다. 공고의 실제 신청과 수료 여부는 외부 시스템에서 별도로 확인해야 합니다.

비로그인 첫 방문 시 튜토리얼이 한 번 열리며, 이후 랜딩 화면의 이용 방법에서 다시 볼 수 있습니다. 목표별 화면은 굿길 공개 프로그램과 교외 공고의 제목 키워드를 목표 분야와 비교해 관련 목록을 보여줍니다. 활동일·참가 자격을 자동 판정하거나 필수 순서로 연결하지 않으며, 일정·조건은 원문 확인이 필요합니다. 발표 모드에는 시연용 예시도 포함됩니다.


## 목표별 기회와 준비 계획

목표별 화면은 교내 굿길 공개 목록과 교외 공고를 선택한 목표의 제목 키워드로 분류합니다. 결과는 실제로 모집 중이라는 보장이 아니며, 수집 시점 이후 변경될 수 있습니다. 교내 활동은 선택 가능한 준비 방법이며 교외 공고의 신청 조건이 아닙니다. 실제 활동일과 교외 공고 접수 시점의 선후 관계는 원문에서 확인해야 합니다.

저장한 공고의 `준비 계획 만들기`는 마감일을 기준으로 일반적인 세 가지 확인 일정을 초안으로 제시합니다. 날짜와 내용을 확인·수정하고 명시적으로 추가해야 캘린더에 기록됩니다. 마감일을 모르면 사용자가 직접 기준 날짜를 입력해야 하며, 자동 추출한 제출 의무나 필수 일정이 아닙니다. 이미 추가한 초안은 중복해서 추가되지 않고, 캘린더에서 수정·삭제할 수 있습니다.

신청 정보 요약은 수집된 대상·조건·마감·출처를 표시합니다. 굿길의 구조화된 학적·학년 정보에 한해 일부 불일치 가능성을 안내하며 신청 자격을 확정하지 않습니다. 학교 공지의 게시일을 마감일로 사용하지 않습니다.

앱을 열면 저장한 공고 중 마감 7일 이내 항목을 홈에 안내합니다. 새로 빌드된 수집본에서 같은 저장 공고의 확인 가능한 마감일이 저장 당시와 다르면 준비함에 차이를 표시합니다. 출처에 없는 공고를 취소로 간주하지 않습니다. 현재 백그라운드 발송이나 이메일·푸시 알림, 자동 수집은 제공하지 않습니다.
